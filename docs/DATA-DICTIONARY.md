# 夜班工时与工资

班次属于shift_day；计划结束时间不大于开始时间时跨到次日。打卡是带偏移的时间，先存UTC，再用Asia/Shanghai拆分实际日历日。休息区间按夜班日期归属处理，先从实际工作区间扣除。单班最多18小时，打卡须为整分钟。缺IN或OUT整班隔离，不猜补卡。

按实际日历日判断法定假日、周末，法定假日优先3倍、周末2倍、工作日8小时内1倍、超过8小时1.5倍；正常分钟按同员工同日累计，跨班片段共享阈值。参数holidays可传日期列表，默认仅2026-10-01。金额按片段Decimal计算到分，paid为实发工资，差额为应发减实发。此规则用于样例计算，不替代当地劳动法规。

## 通用采信约定

CSV按UTF-8 BOM、UTF-8、GB18030回退，保留逻辑记录结束行号；引号内换行由CSV解析。重复表头单独计数，列数不齐隔离。编码与ID按字符串保形。缺失哨兵为 `-`、`N/A`、`NULL`、`未知` 与空串；不得作为零。数值先NFKC归一、去千分位，再用Decimal。日期采用ISO；时间必须带偏移并转UTC。空文件、全空行、仅表头分别返回EMPTY_FILE、BLANK_FILE、HEADER_ONLY。

重复键为(id,version)，完全相同行去重；同键内容冲突则整组隔离，不取最后一行。行数对账：输入=采纳+隔离+空行+重复表头+完全重复。运行幂等键由输入字节、参数与规则版本计算。

同一员工/归属日/方向的最高版本若有时刻、时薪、班次、休息或实发金额冲突，则整班隔离；选中IN与OUT的时薪、班次起止与休息起止也必须完全一致。

## 可付裁决

每个有计薪结果的班次在截止时形成且只形成一份可付结果，页面与导出只呈现这份结果。结果逐项对应：实际打卡人、排班人、替班依据、调休、实发收款人与金额。

排班人来源为参数 `roster`（`employee`、`shift_day`、`shift_start`、`shift_end`，时间HH:MM）。本人打卡命中本人排班按排班可付；未命中时取未被本人占用的同槽位排班人，候选多于一个为排班冲突，没有候选为未排班打卡；不传 `roster` 时排班人即打卡人，或取审批指名的排班人。

替班依据为参数 `substitutions`（`id`、`shift_day`、`scheduled`、`actual`、`status`、`approved_at`、`settle`）。`status` 为已批准、待批、驳回；`settle` 为付薪或调休，默认付薪。仅已批准且 `approved_at` 不晚于参数 `cutoff`（必须带时区）的审批生效。生效且条款为付薪时实发给实际打卡人；条款为调休时该班全部分钟记为打卡人调休、不付现。无有效审批、审批冲突、排班冲突、未排班打卡、两人同顶一班均为挂起：金额留痕可见但不计入任何人实发。

不变量：应发合计=本次实发+挂起+转调休金额；工分钟=实发分钟+挂起分钟+调休分钟，每分钟只有一个去向；被顶班班次的排班人不得任何付薪与调休。裁决不平衡则归档未就绪、导出被拒。

审批、排班或截止变化使运行键变化，新批次成为当前结果，旧批次结果失效：历史批次仍可查询但导出返回409 SUPERSEDED。同一输入复用同一批次，重复执行不重复付款。新输入计算失败在入库前抛错，旧批次的原始打卡、隔离原件与参数不丢失。无效排班条目与无效审批不生效并列入问题清单；未匹配任何班次的审批同样列出。
